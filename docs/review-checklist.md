# 문서 리뷰 체크리스트

이 문서는 `rules/registry.toml`에서 `tools/render_review_checklist.py`로 생성합니다. 직접 고치지 않습니다.

가이드 저장소의 `doc-review` 워크플로에서 Claude가 PR을 리뷰할 때 이 체크리스트를 판정 기준으로 사용합니다. 각 저장소의 CLAUDE.md 문장 규칙도 함께 따릅니다.

## 리뷰 방법

- 판정 대상은 PR에서 바뀐 Markdown 줄입니다. 바뀌지 않은 줄은 지적하지 않습니다.
- 위반이 분명할 때만 지적합니다. 확신이 없으면 지적하지 않습니다.
- 지적 하나에 규칙 ID 하나를 붙입니다. 근거를 한두 문장으로 적고, 고친 문장을 제안합니다.
- 같은 줄에 같은 규칙으로 이미 남긴 지적이 있으면 다시 남기지 않습니다.
- 소유자 확인 규칙은 판정하지 않고 요약 댓글에 확인할 위치만 적습니다.
- 리뷰 결과는 머지를 차단하지 않습니다. 작성자는 지적마다 수정하거나 사유를 답글로 남깁니다.
- 지적과 요약 댓글도 CLAUDE.md의 문장 규칙을 지켜 작성합니다.

## 1. 판정 규칙

Claude가 변경된 줄마다 판정합니다.

### DASH-SUBSTITUTE. 대시를 콜론이나 괄호로 단순 치환 금지

- 적용 범위: 전체 저장소
- 판정 기준: 대시를 지운 자리에 콜론이나 괄호만 넣어 앞뒤 구의 관계가 여전히 생략된 문장이면 위반입니다. 두 문장으로 나누거나 관계를 드러내는 한 문장으로 합쳐야 합니다. 라벨형 `**라벨.** 본문`과 정의 목록은 위반이 아닙니다.
- 잘못된 예: 단편적 해결의 한계: 동시 해결 필요
- 고친 예: 단편적 해결로는 한계가 있습니다. 동시에 해결해야 합니다.

### STR-CODE-FENCE. 코드 펜스는 실제 코드와 마크업에만 사용

- 적용 범위: 전체 저장소
- 판정 기준: 코드 펜스 안에 명령, 설정, 코드, 마크업이 아닌 일반 문장이나 표 대용 텍스트가 들어 있으면 위반입니다. 다이어그램 문법(mermaid 등)은 코드로 봅니다.

### LINK-XREF. 상호참조는 'N.M절', 다른 편은 '시리즈 ④의 2.3절' 형식

- 적용 범위: vcf-private-ai
- 판정 기준: 같은 가이드 안의 참조가 'N.M절'이나 문서 번호가 아닌 표현(위 섹션, 다음 장 등)으로만 되어 있거나, 다른 편을 가리키면서 편 기호(①–⑦)를 빠뜨렸으면 위반입니다.

### CNT-UNVERIFIED. 공식 문서로 확인되지 않은 내용은 '확인 필요'로 표시

- 적용 범위: 전체 저장소
- 판정 기준: 공식 출처 링크가 없는 버전 정보, 수치, 제품 동작 서술을 단정형으로 적었으면 위반입니다. 출처 링크를 붙이거나 '확인 필요'로 표시해야 합니다. 일반 원리 설명과 문서 안에서 계산한 값은 대상이 아닙니다.

### CNT-JUDGMENT. 적합한 경우, 적합하지 않은 경우, 장단점을 함께 서술

- 적용 범위: 전체 저장소
- 판정 기준: 새로 추가한 방식, 구성, 도구 권고가 절차만 적고 언제 적합한지와 장단점을 적지 않았으면 위반입니다. 단순 사실 서술과 용어 정의는 대상이 아닙니다.

### CNT-MISFIT. 권하는 접근이 맞지 않는 조건과 그때의 대안을 서술

- 적용 범위: 전체 저장소
- 판정 기준: 권하는 접근을 새로 추가하면서 그 접근이 맞지 않는 조건과 그때의 대안을 같은 절에 적지 않았으면 위반입니다.

### CNT-FIVE-ELEMENTS. 운영 기준은 무엇을, 어떤 기준으로, 누가 언제, 어떻게 측정, 어떻게 개선의 다섯 요소로 서술

- 적용 범위: vcf-private-ai, vcf-private-ai-apps
- 판정 기준: 운영 기준(점검, 측정, 판정 기준)을 새로 서술하면서 무엇을, 어떤 기준으로, 누가 언제, 어떻게 측정하고, 어떻게 개선하는지 가운데 빠진 요소가 있으면 위반입니다.

### CNT-FILLED-EXAMPLE. AX 가이드는 양식 대신 끝까지 채운 가상 예시 수록

- 적용 범위: enterprise-ax-methodology
- 판정 기준: 빈칸 양식이나 채워 넣을 자리만 있는 표를 추가했으면 위반입니다. 끝까지 채운 가상 예시로 바꿔야 합니다.

### PRS-CONCLUSION-FIRST. 결론을 먼저, 근거를 뒤에

- 적용 범위: 전체 저장소
- 판정 기준: 단락이나 절이 배경과 근거를 길게 나열한 뒤 마지막에야 결론을 제시하면 위반입니다. 결론 문장을 앞으로 옮기는 수정안을 제시합니다.

### PRS-ONE-MEANING. 한 문장에 한 의미, 주어와 서술어를 가깝게 배치

- 적용 범위: 전체 저장소
- 판정 기준: 한 문장에 서로 다른 주장이 둘 이상 들어 있거나, 수식어가 겹쳐 해석이 둘 이상으로 갈리거나, 주어와 서술어가 멀어 끝까지 읽어야 뜻이 잡히면 위반입니다.

### PRS-TERM-FIRST-USE. 핵심 용어는 처음 나올 때 주어와 동작을 갖춘 문장으로 정의, 같은 산출물 안에서 반복 설명 금지

- 적용 범위: 전체 저장소
- 판정 기준: 이 문서에서 처음 나오는 전문 용어나 약어를 정의 없이 사용했으면 위반입니다. 업계 용어(하네스, 루프, 래퍼, control plane 등)를 사용하면서 실제 동작을 적지 않은 경우도 위반입니다. 같은 문서에서 이미 정의한 용어를 다시 설명한 경우도 지적합니다.

### PRS-ABSTRACT-NOUN. 계층, 구조, 루프 같은 추상 명사로 끝나는 설명을 실제 동작 서술로 교체

- 적용 범위: 전체 저장소
- 판정 기준: 설명이 계층, 구조, 루프, 체계, 프레임 같은 추상 명사로 끝나 실제로 무엇이 무엇을 하는지 드러나지 않으면 위반입니다.

### PRS-NOUN-CHAIN. 명사구 3개 이상 연쇄 금지, 동사문으로 분해

- 적용 범위: 전체 저장소
- 판정 기준: 명사구가 셋 이상 이어져 한 번 더 해석해야 뜻이 잡히면 위반입니다. 동사문으로 분해한 수정안을 제시합니다.
- 잘못된 예: 운영 효율성 개선을 위한 자동화 체계 도입 방안
- 고친 예: 운영을 자동화해 사람이 직접 처리하는 일을 줄이는 방법

### PRS-TONE. 전문가 대 전문가 어조. 강의식, 연출된 문답, 과장 금지

- 적용 범위: 전체 저장소
- 판정 기준: 강의식 어조(알아볼까요, 기억해 두세요), 연출된 문답(왜 그럴까요? 바로), 근거 없는 과장(놀랍게도, 무려)이 있으면 위반입니다.

### PRS-TERM-CONSISTENT. 한 단락에서 같은 개념은 한 용어로 통일

- 적용 범위: 전체 저장소
- 판정 기준: 한 단락 안에서 같은 개념을 서로 다른 용어로 가리키면 위반입니다.

## 2. 소유자 확인 규칙

Claude는 판정하지 않습니다. 해당하는 위치를 요약 댓글에 "소유자 확인 필요"로 적습니다.

- **CNT-SOURCE-QUALITY.** 핵심 수치는 1차 출처까지 추적, 통제 실험인지 조건이 다른 비교인지 구분. 핵심 수치의 출처가 2차 자료(블로그, 기사, 리뷰)이거나, 조건이 다른 결과를 나란히 놓고 비교했으면 소유자 확인 항목으로 요약에만 적습니다.
